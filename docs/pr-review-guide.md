# PR 자동 코드 리뷰 운영 가이드

## 운영 리스크와 대응

| 리스크 | 대응 원칙 |
| --- | --- |
| PC 절전이나 앱 종료로 예약 실행이 누락될 수 있다. | 운영 PC와 Codex 앱을 실행 상태로 유지한다. 작업을 재개할 때 실행 환경과 GitHub 연결을 확인한다. |
| 코드 조회가 불완전하거나 근거 없는 지적이 포함될 가능성이 있다. | diff 전체와 필요한 주변 코드를 확인하고 실제 결함이나 문서 오류만 설명한다. 필요한 코드를 조회하지 못하면 검토 완료로 처리하지 않는다. |
| PR에서 변경한 지침이 리뷰 기준에 영향을 줄 수 있다. | base SHA에 해당하는 AGENTS.md와 변경 경로의 지침을 기준으로 리뷰한다. PR에서 변경한 지침으로 이를 대체하지 않는다. |
| 동일 커밋에 리뷰 댓글이 중복 게시될 수 있다. | 저장소·PR 번호·head SHA를 기준으로 기존 일반 댓글 전체를 확인한다. 동일 SHA의 자동 리뷰가 있으면 생략하고, 기존 댓글을 확인하지 못하면 게시를 보류한다. |
| 검토 도중 PR 상태나 head SHA가 바뀔 수 있다. | 게시 직전에 대상 조건과 SHA를 다시 확인한다. 조건이 달라지면 게시하지 않고, SHA가 바뀌면 최신 변경을 다시 검토하거나 다음 실행으로 보류한다. |
| 댓글 게시가 실패하거나 등록 여부가 불확실할 수 있다. | 게시 후 댓글을 재조회한다. 결과가 불확실하면 기존 댓글을 먼저 확인하고 재전송 여부를 판단한다. 실제 등록을 확인한 경우에만 게시 완료로 처리한다. |
| 일부 단계나 PR의 실패가 전체 완료로 잘못 기록될 수 있다. | 조회·지침 확인·리뷰·게시·게시 확인 중 실패한 단계와 PR별 처리 상태를 기록한다. 읽기 전용 조회 결과를 리뷰 게시 완료로 간주하지 않는다. |

자동화가 수행하는 외부 변경은 **PR 일반 댓글 작성**으로 제한한다.
코드 수정, 커밋, push, PR 생성, PR 상태 변경, 라벨 변경,
정식 리뷰 제출, 승인 및 머지는 수행하지 않는다.

## 개요

Codex 앱의 시간 기반 정기 작업으로 저장소의 PR을 조회하고,
변경 내용을 한국어로 리뷰하여 PR 일반 댓글에 게시한다.

## 리뷰 대상

- base 브랜치가 develop인 열린 PR
- Draft가 아닌 PR
- 작성자 제한 없음
- 작업 설정 이전에 열려 있던 PR도 포함

## 처리 절차

1. 열린 PR 목록을 페이지네이션 전체에 걸쳐 조회한다.
2. PR의 상태, base SHA, 최신 head SHA를 확인한다.
3. base SHA에 해당하는 AGENTS.md와 변경 경로에 적용되는 지침을 읽는다.
4. 기존 PR 일반 댓글을 조회하여 동일 head SHA의 리뷰 게시 여부를 확인한다.
5. 최신 diff 전체와 판단에 필요한 주변 코드를 읽고 리뷰한다.
6. 게시 직전에 PR 상태와 head SHA를 다시 확인한다.
7. 대상 조건과 SHA가 유지되면 PR 일반 댓글을 작성한다.
8. 댓글을 다시 조회해 실제 등록 여부를 확인한다.

## 리뷰 기준

- 실제 결함이나 문서의 실제 오류를 근거와 함께 설명한다.
- 문제의 발생 조건과 영향을 구체적으로 작성한다.
- 문제가 없으면 '발견한 문제 없음'이라고 작성한다.
- 취향에 따른 지적이나 불필요한 리팩토링 제안은 제외한다.

## 댓글 구성과 게시 기준

중복 방지 기준은 저장소, PR 번호, 검토한 head SHA이다.
게시 완료 여부의 원본은 GitHub에 실제 등록된 댓글이다.

댓글에는 다음 내용을 포함한다.

- 검토한 head SHA 전체
- 변경 요약
- 발견한 문제와 근거 또는 '발견한 문제 없음'
- 식별용 표식: `<!-- pr-review-head:전체_HEAD_SHA -->`

## 운영 관리

- 설정 변경: 자동화가 연결된 채팅이나 작업 설정에서 주기와 지침을 수정한다.
- 일시 중지: 앱의 예약/자동화 화면에서 해당 작업을 일시 중지한다.
- 재개: 실행 환경과 GitHub 연결을 확인한 뒤 작업을 활성화한다.
- 담당자 변경: 새 담당자의 환경에서 자동화를 설정하고 동작을 확인한 뒤 기존 작업을 중지한다.

실행 기록과 검증 결과는 별도 Notion 문서에서 관리한다.
